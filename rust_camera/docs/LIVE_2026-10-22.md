## Key measurements

- 12 MP JPEG: 4096×3072, ~1.3 MB.
- RAW 12 DNG: 4096×3072, 25,166,262 bytes.
- RAW 50 DNG: 8192×6144, 100,663,734 bytes; TIFF `II 2A`, 23 IFD entries,
  DNGVersion 1.4, black level 64, white level 1023.
- HDR: 3 frames at ~0.25 s intervals; fused output ~2.2 MB; ~2.3 s end-to-end.
- Session start: ~50 ms (previously ~2 s waiting for an `onReady` callback that
  this HAL never invokes).
- Lens restart: ~50–100 ms; camera IDs 3/0/4.

## 50 MP findings

- The static metadata advertises 8192×6144 RAW sizes, but the standard stream list
  has no 8192×6144 JPEG output.
- With `com.oneplus.camera` + vendor session parameters
  (`ultra.resolution.mode = 1`, `EnableIdealRAW = 1`, package name), **RAW 50 works**.
- The 8192×6144 JPEG reader still receives a **1920×1440** JPEG from the HAL.
  The engine now parses the JPEG SOF and refuses to save it as a 50 MP photo.
- 50 MP JPEG likely requires the system camera path/signature; use RAW 50 for
  maximum resolution.

## Package identity

- The app is installed as `com.oneplus.camera`, which is in the Chi HAL whitelist.
- The old patched stock clone with the same package was uninstalled.
- The stock camera `com.oplus.camera` remains enabled and unaffected.
- To restore the clone, uninstall OpOpenCam and reinstall
  `stock_apk/OnePlusCamera_patched.apk`.
